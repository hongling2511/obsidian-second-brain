## 📄 概述

《pi的设计艺术》是一部深入剖析 pi-mono 这一生产级 Coding Agent 运行时的设计决策之著作。

**核心论题**："用最薄的核心支撑最丰富的产品"（How to support the richest possible products with the thinnest possible core）

**基本信息**：
- 以 pi-mono v0.66.0（2026年4月）为蓝本
- 涵盖约12万行 TypeScript 代码的架构分析
- 非源代码指南，而是对"为什么做这个设计决策"的深层剖析
- 目标读者：有丰富工程经验、希望理解 Agent 系统设计的开发者

**阅读价值**：
通过 pi 的真实案例，学习如何在复杂性和简洁性之间找到平衡点，如何通过分层架构和极简核心构建高度可扩展的 AI 应用系统。

## 💡 关键洞见

1. **运行时思维**：pi 是运行时而非库。关键问题不是"如何调用 LLM"，而是"调用 LLM 后会发生什么"。这决定了整个架构的组织方式。

2. **洋葱架构的实践**：通过严格的4层依赖关系（UI → 产品 → 运行时 → 基础设施），实现清晰的关注点分离和易维护性。

3. **无状态循环引擎**：将 Agent 循环设计为纯函数，使其可组合、易测试、支持多形态UI的无缝切换。

4. **Skill 即 Markdown**：选择 Markdown 而非代码来定义 AI 能力，换来零依赖、人类可审计、版本控制友好的收益。

5. **"不在核心里构建"就是"从低层机制组合"**：看似减少功能，实际上通过层层组合达到更强的灵活性和可扩展性。

6. **三大回调控制一切**：`execute`（做什么）、`beforeToolCall`（权限控制）、`transformContext`（上下文塑形）三个回调贯穿整个 Agent 行为。

7. **协议式 vs 框架式**：协议式设计提供更多控制权但学习曲线陡，框架式设计易上手但灵活性受限。pi 选择了协议式，换来强大但需要用心学习。

8. **最薄核心的代价与收益**：核心代码量只占24%，却能驱动CLI、Slack、Web、RPC等100%的产品形态。这要求核心更纯粹、更深思熟虑。

9. **有损变换的艺术**：通过精心设计的压缩策略（状态压缩、消息精简），在 Token 成本和信息保留度之间找到最优点。

10. **契约优于继承**：事件流契约、工具 Schema、RPC 协议等基于契约的设计，比继承关系更灵活且版本兼容性更好。
